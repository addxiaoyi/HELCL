# 前端交互细节优化

本轮从已验提交 `1fbdeae746f64e5cc001f0726e340151265acde7` 继续，保留 WPF、Avalonia Desktop 与 Mobile 的视觉风格。变更集中在九组已复现的输入、确认与恢复问题，另修正任务历史说明。

## 修补内容

- WPF 统一通行证在表单内验证服务器 ID，并仅传输规范化的有效 ID；格式错误不再关闭表单或提交后台登录任务。该检查不等于真实账号认证成功。
- WPF 文本、密码及选择控件在修改时清除上次字段错误；密码表单先聚焦输入框，异步保存失败保留草稿并恢复原编辑焦点。
- 手机 AI 重试保留新草稿；编辑旧问题需确认替换，并复核确认期间的草稿与失败目标；清空聊天同时移除旧重试状态。
- 手机取消确认框后恢复仍然可用的原控件焦点；已隐藏、禁用、移除的入口不会被重新聚焦。离开资源页再返回时恢复原列表阅读位置。
- 桌面 AI 复制失败给出安全的重试反馈。日志发送批准绑定原输入；确认期间出现的新预览或新草稿不会被旧批准发送或清空。AI 配置保存期间仅锁定配置表单，失败恢复可编辑状态并保留输入。
- 桌面任务空态明确最近 100 条已结束任务保存在本机，避免仍声称只有本次会话记录。

实现与回归细节：[WPF](frontend-details-wpf.md)、[手机](frontend-details-mobile.md)、[桌面](frontend-details-desktop.md)。本轮在原有百项方案上补充已证实的边界，没有将原生设备待测状态改为通过。

## 验收与范围

失败先行回归记录 WPF 7 条失败、手机 6 条失败、桌面 3 组失败；修补后对应回归通过。新增实际 UI 检查分别包含 WPF 14 条、手机 15 条、桌面 6 项结果，并通过既有复核链路强制执行。测试使用隔离目录、受控 RPC、异步门控与本地夹具，不调用真实登录或 AI 服务，不提交生成配置及临时密钥。

整合后的本地构建、单测、实际 UI 和 GitHub 结果分别记录于 `TestResults/frontend-details-20261120/`。Android 原生验收强制读取普通与 200% 会话的新手机细节回执；保留键盘、返回、安全区、进程重启、加密凭据及原有字体断言。工作流继续覆盖 Windows、Linux、macOS Intel、三种尺寸普通/远程预览及完整 WPF 应用。

物理触控、TalkBack/桌面读屏、厂商键盘和不同刘海设备仍待专项实测。没有合并、正式发布或生产部署。
