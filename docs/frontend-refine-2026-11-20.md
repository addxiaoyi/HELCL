# 三端审美细节精修

本轮从已验提交 `e8403e1f1f058bb27927d2fa0628f889cbebd812` 继续，保留现有品牌、共享 66 种矢量图标、页面入口与业务流程。精修集中在文字层级、表面层次、阅读空间和信息密度，没有引入动画或新依赖。

## WPF 首页

安装卡的辅助标题、说明与新闻行使用更清楚的字号和行距关系。空态隐藏启动配置栏时，布局同时移除该栏留下的列宽和间隙；空状态区没有状态或进度时也收起。窄窗相同数据对照中，新闻区域提前约 45px，主操作保留 44px。折叠与恢复、长标题、明暗 900/1180 视口及整页 200% 布局分别验证。

## Avalonia Desktop

在系统没有提供模糊效果时，窗口使用清晰的实色背景，避免浅色灰雾降低文字可读性；支持 Acrylic、Blur 或 Mica 时仍保留原有玻璃参数和用户偏好。主题变化与透明能力变化触发背景同步，显式背景不再与 XAML 资源绑定相互覆盖。

实例列表减少大面积空白卡面，检视器按内容收拢并保留窄窗滚动；操作分清主次，侧栏实例数量有独立间距，长名称和固定标记不会挤出操作按钮。同一数据的无模糊后备对照中，浅色辅助文本对比约 3.9→5.9，宽窗检视器约 554px→357px。

## Mobile

分组表面改为安静的纯色与细分割，减轻灰渐变和边缘高光；标题、实例值、标签与资源行的层级更明确，次要获取按钮减少装饰但保留触控面积。异步资源模板也遵循当前用户字号；窄屏大字下重新排列获取动作，给资源名称更完整的阅读空间。重复刷新、离开返回与大字布局保留此前草稿、焦点和滚动位置回归。

末轮 Linux 截图还发现账号值随列宽调整后没有右对齐。补充同数据的明暗主题边界检查后，普通行的账号和实例值右端对齐，大字体上下排列时统一左对齐。

实现与原始对照见 [WPF](frontend-refine-wpf.md)、[桌面](frontend-refine-desktop.md)、[手机](frontend-refine-mobile.md)。截图使用相同隔离数据，不把模拟内容、受控故障状态或缩放布局当作真实账号、原生系统磨砂或物理 DPI 认证。

## 验收记录

真实布局、渲染像素和文字对比度检查接入既有三端 UI 流程；保留图标、表单、异步恢复、资源分页、200% 字体、键盘返回、系统密钥库和进程重启验收。构建、单测、失败先行回执及同数据截图保存在 `TestResults/frontend-refine-20261120/`，最终结果按整合提交与 GitHub 回执登记。

本轮 WPF 本地完整单测曾遇到既有存档导入目录提升的文件访问失败，未修改 Core 或断言；独立两例复核结果及完整日志均保留。完整非增量 Core 构建仍有既有平台和过时 API 警告，没有隐藏警告。物理触控、TalkBack/桌面读屏、原生高对比与显示缩放、厂商键盘和不同刘海设备仍待专项实测。未合并、正式发布或部署。
